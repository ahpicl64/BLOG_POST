# 보안 조치 (추후)

## 🔐 Spring Boot 백엔드 보안 설정 분석

### **현재 보안 설정 상태**

### **1. 인증/인가 설정 (SecurityConfig.java)**

```json
java
.requestMatchers("/**").permitAll() // 모든 권한 제한 해제 (임시)
```

⚠️ 현재 문제점:
• **모든 API 엔드포인트가 인증 없이 접근 가능**
• 주석 처리된 실제 보안 정책이 비활성화됨
• "로그인 이전 테스트를 위하여 임시로" 라고 명시되어 있음

### **2. CORS 설정**

```json
java
config.setAllowedOrigins(List.of(
"[http://localhost:3000](http://localhost:3000/)",
"[https://tio-style.com](https://tio-style.com/)",
"[https://www.tio-style.com](https://www.tio-style.com/)"
));
```

✅ 올바른 설정:
• 허용된 도메인만 접근 가능
• 적절한 CORS 헤더 설정

## 🚨 ALB에서 Spring 서버 직접 접근의 보안 위험성

### **현재 ALB 라우팅 구조**

```json
CloudFront → ALB → {
						Default: Spring Boot (백엔드)
						/api/*: Spring Boot (백엔드)
						/*: Next.js (프론트엔드)
}
```

### **보안 문제점**

### **1. 인증 우회 가능**

- **ALB 직접 접근**: [http://TIO-ALB-173623777.ap-northeast-2.elb.amazonaws.com/api/users](http://tio-alb-173623777.ap-northeast-2.elb.amazonaws.com/api/users)
• **CloudFront 우회**: 인증 로직을 건너뛸 수 있음
• **현재 상태**: 모든 API가 permitAll()로 설정되어 더욱 위험

### **2. CORS 정책 우회**

- ALB 직접 접근 시 CORS 검증 우회 가능
• 악의적인 도메인에서 API 호출 가능

### **3. Rate Limiting 우회**

- CloudFront의 Rate Limiting 정책 우회
• DDoS 공격에 취약

## 🛡️ 권장 보안 강화 방안

### **1. 즉시 적용 (High Priority)**

### **A. Spring Security 정책 활성화**

```json
java
// SecurityConfig.java 수정 필요
.requestMatchers("/auth/**", "/health", "/swagger-ui/**").permitAll()
.requestMatchers("/api/admin/**").hasRole("ADMIN")
.requestMatchers("/api/**").hasAnyRole("USER", "ADMIN")
.anyRequest().authenticated()
```

### **B. ALB 보안 그룹 제한**

- **현재**: ALB가 인터넷에서 직접 접근 가능
• **권장**: CloudFront에서만 ALB 접근 허용

### **2. 중기 적용 (Medium Priority)**

### **A. API Gateway 도입**

CloudFront → API Gateway → ALB → Spring Boot

### **B. WAF (Web Application Firewall) 적용**

- SQL Injection, XSS 공격 방어
• Rate Limiting 강화

### **C. VPC 내부 통신으로 제한**

- ALB를 Internal Load Balancer로 변경
• CloudFront에서만 접근 가능하도록 설정

### **3. 장기 적용 (Low Priority)**

### **A. Zero Trust Architecture**

- 모든 요청에 대한 인증/인가 검증
• 마이크로서비스 간 mTLS 적용

### **B. API 버전 관리 및 모니터링**

- API 버전별 접근 제어
• 실시간 보안 모니터링

## 🎯 결론

현재 상태는 매우 위험합니다:

1. 모든 API가 인증 없이 접근 가능
2. ALB 직접 접근으로 보안 정책 우회 가능
3. 프로덕션 환경에서 임시 설정이 그대로 유지됨

즉시 Spring Security 설정을 활성화하고, ALB 접근을 제한하는 것이 필요합니다.
